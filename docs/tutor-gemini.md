# AI Tutor: Gemini Hydrogen

The tutor chat, its single concise truncation retry, and `tutor.saveSession` use the server-only `server/tutorLLM.ts` adapter. It calls Google's native `v1beta/models/gemini-4-hydrogen:generateContent` endpoint with `systemInstruction`, ordered `user`/`model` contents, and `generationConfig.maxOutputTokens`. Adjacent same-role turns are combined into ordered text parts. The current tutor API accepts text only; this adapter does not add images, files, tools, or structured-output options.

Configure `GEMINI_API_KEY` as a server deployment secret, never a `VITE_` variable. The key is sent only in `x-goog-api-key`, not a URL or log. A missing/blank key does not prevent startup: tutor calls use the existing `invokeLLM` Claude path. Google network/HTTP failures, malformed responses, or no visible text also recover through that unchanged path. Existing Forge/Anthropic credentials remain necessary for this recovery. Explicit Google safety/refusal responses fail closed without cross-provider retry. Diagnostics contain no raw Google errors, bodies, prompts, or keys.

There is one Google request per adapter invocation, a 30-second deadline covering headers and response body, a 2 MiB response limit, and caller-abort propagation without fallback. The existing fallback retains its own bounded request policy. Chat still makes at most one concise recovery attempt after truncation; `MAX_TOKENS` maps to the existing `length` finish reason. Empty output, including thought-only output, is not presented as a successful explanation. Only visible text parts are returned; thought parts and thought signatures are ignored. Usage is normalized to the existing token fields, including thinking tokens in completion usage.

No unverified `thinkingConfig` is sent. Provider-default thinking applies. Chat retains its existing output-token budget; short summaries receive a minimum Google generation budget of 2,048 tokens to leave thinking headroom (Claude fallback still receives the original summary budget). The parent deployment pilot verified this native request shape with synthetic water-treatment content. Production secret availability and a deployment smoke check must still be confirmed by the release owner.

Shared `server/_core/llm.ts`, scheduled email generation, tutor-health probes, tools/structured callers, pricing, access limits, quota handling, database writes, and customer records are unchanged. The existing tutor-health probe therefore checks the legacy recovery path, not Gemini; it must not be interpreted as proof of Gemini availability.

`server/tutorLLM.test.ts` uses synthetic fixtures and mocked fetch/fallback only. Run it and the tutor regression tests through `scripts/test-safety.cjs` with a credential-free environment; router suites additionally require the guard-approved placeholder `STRIPE_SECRET_KEY=sk_test_ci_placeholder`. Do not run live credential tests with customer prompts.
