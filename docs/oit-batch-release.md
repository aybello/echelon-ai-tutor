# OIT batch release

Scope: the 972 retained questions in manifest version `2026-09-09-v4`. The exact-version OIT revision updates the 782 user-approved conceptual rows already present in production while preserving their `bankKey`, `questionNum`, review status, and learner-attempt history. The remaining 190 calculation rows are compared and left unchanged. Regeneration preserves the earlier exclusions; always validate and inspect the generated diff.

1. Run `node scripts/update-oit-question-banks.mjs`. This validates package structure, calculations, source metadata, answer patterns, and package duplicates, then prints the exact package and committed-baseline SHA-256 tokens. It does not connect to a database.
2. With the intended database configured, run `node scripts/update-oit-question-banks.mjs --database`. This opens a rollback-only reconciliation transaction and requires every row in both banks to match the committed production baseline before planning a revision. Retain the output. It must report exactly 489 Water rows and 483 Wastewater rows, with 393 and 389 revisions respectively, no errors, and unchanged visible totals.
3. Do not bypass a drift error. Any row that no longer matches the committed baseline, is missing, has an unsafe review status, or has a duplicate ID blocks the complete update. For missing rows, use the existing checksum-confirmed additive importer and repeat reconciliation. A new baseline may be captured only after an independent review of the changed production state.
4. Capture the current production baseline with `node scripts/snapshot-oit-production-baseline.mjs`, persist it with `pnpm tsx scripts/store-oit-production-baseline.ts`, and retain the generated evidence record, commit SHA, and secure storage key. The baseline contains the complete pre-update content for all 972 rows, permitting item-for-item recovery without deleting question identities or learner attempts.
5. After the package, baseline, backup evidence, and read-only reconciliation all match, run `CONFIRM_OIT_CONTENT_UPDATE=<full-package-sha256> CONFIRM_OIT_BASELINE=<baseline-sha256> BACKUP_EVIDENCE_ID=<baseline-sha256> node scripts/update-oit-question-banks.mjs --apply`. This locks both bank metadata rows and all 972 package rows, repeats every comparison before writing, updates only the 782 confirmed content records, verifies unchanged learner-visible counts, and increments metadata versions only for affected banks. A failure rolls back the entire batch.
6. Run the reconciliation command again. It must report zero revisions, zero errors, 489 matching Water rows, and 483 matching Wastewater rows. Then verify public Water and Wastewater practice, flashcards, and server-issued mock exams against the newly deployed server release without creating customer data or exposing answer keys.

If recovery is necessary, use the retained baseline artifact to restore only the changed content columns for the recorded 782 rows after a read-only comparison confirms that they still match the deployed revision. Never delete questions, change question IDs, or delete learner-attempt history.
