# Game content scaling plan (draft)

Status as of 2026-11-14. This is a planning note, not a commitment. Counts are approximate.

## Where we are

- Two courses, `oit` and `oit-ww`, have draft tables written from the operator handbook and official Ontario pages. Both are near 500 per mode counting the original bank plus drafts.
- Only the original banks and `oit` batches 1 to 4 are served. Everything else waits for the publishing step that binds a review record to each item.
- Checks so far: about 2,800 draft statements were checked against operator textbooks. None was clearly contradicted. A bit under half had a supporting passage. About 15 wording fixes were made. The rest is unverified, mostly because the key Ontario and distribution books are too large for the connector.

## Why 500 per mode for every course does not scale

- 38 courses x 6 modes x 500 is about 114,000 items. At the pace so far (about 500 to 600 reviewed items per round of three writers) that is roughly 200 rounds.
- Every table also needs a read-through and a source check.

## Proposed approach

1. **Shared concept pool.** Classes 1 to 4 teach much of the same material at different depths. Write each concept once, tag it with the lowest class level it fits, and serve it to every course at or above that level. Write extra items only for the depth that differs.
2. **Staged target.** About 150 per mode for every course first. Raise a course to 500 only when usage shows it earns it.
3. **Demand first.** Rank courses by quiz and mock attempts, purchases and previews. Use the Utilities Kingston operators' exams as a known priority. Build the top five or six first.
4. **Source first.** Writers work from named chapters of readable books and the Ontario facts file. Every table section names its source. A second check against the books runs before anything is served.
5. **Independent review.** Manus's second-model review runs on each batch. A named person in the field spot-checks a sample.
6. **Measure.** Once game progress is saved, look at completion by mode, drop-off, and which modes feed readiness. Stop writing modes nobody uses.
