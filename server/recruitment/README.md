# Recruitment Assessment backend

V1 identity-locked knowledge assessments for existing current Annual organization seats. `server/routers/recruitmentRouter.ts` exposes ten shared-schema procedures registered in the root router. The manager copies `/recruitment/:assignmentId`. No email is sent and that UUID is not authentication.

Candidate start/save/submit handlers bind the rendering epoch, exact reviewed DTO and synchronously admitted authorized receipt. A replacement receipt fences old callbacks before passive rendering. Consent additionally binds the accepted invitation DTO and is synchronously cleared by uncheck, session reset, receipt replacement and unmount. Submission confirmation has a distinct per-opening exact DTO/epoch/revision token, invalidated on close or replacement; old callbacks cannot borrow a later same-revision confirmation. Retained handlers cannot adopt a replacement session epoch or dispatch after cleared/freshly replaced authorization.

Usable duplicate invitations require the current locked member email to match the original immutable candidate email, including after governance waits. A changed email requires a new form, not rebinding old evidence. New question counting and sampling reject display-equivalent options using NFC and normal HTML whitespace collapse, preserving meaningful case, superscripts and nonbreaking spaces. New labels containing Unicode default-ignorable formatting characters are excluded to avoid invisible indexed-choice ambiguity. Historical frozen option texts and answer keys remain unchanged.

Manager revocation requires the reviewed expectedRevision under the assignment lock. Changed nonrevoked rows conflict; already-revoked retries are idempotent. An elapsed deadline is finalized and committed before returning a refresh-required conflict, never rolled back or marked revoked by a stale confirmation. A correct-revision completed-row revocation remains supported explicitly by the backend with evidence preserved, but the UI offers revoke only for invited/active rows. UI confirmation is cleared synchronously on exact results refetch, invalidation, denial, removal or changed target; conflicts require a fresh explicit review with no automatic replay. A sent revocation still reconciles its settled success/conflict in the current detail scope even if an intervening same-session read cleared review; stale notices are suppressed, successful links/outcomes removed and fresh reports requested. Session reset/unmount suppress late settlement effects.

## Boundaries and persistence

`access.ts` combines the existing manager reporting resolver with explicit non-course-pass Annual boundaries. Historical Annual reporting remains available when the resolver permits it, without requiring a current Annual term. List, results and revocation recheck the locked organization is active/past_due and non-Flex, and revalidate primary or delegated-manager authorization. Creation, invitation and candidate access require a current active/past_due Annual term, rejecting future non-null term starts while preserving the null-start convention. Candidate procedures require a verified OTP/OAuth identity matching the original invitation email, the original assigned same-org/member seat, canonical active region/plan-permitted course, and a current same-org subscription with exact Annual course sentinel, tier and province. They also invoke central `assertAccess`. Personal or other-team purchases do not satisfy the scoped guard; delegated-manager role alone never grants a seat.

`questions.ts` reads authoritative questions through `getDb`, filters withheld learner content and validates option JSON and correct-answer bounds before counts or selection. `service.ts` samples 5–100 questions with every selected module represented, then locks and validates each selected source before insertion. Creation also compares the current locked module, prompt, ordered parsed options and correct index with the sampled payload; a changed or malformed payload refuses creation without silently resampling. Unrelated explanation edits and equivalent JSON formatting do not invalidate a semantic match. One immutable snapshot is shared by every assignment of a definition. New invitations, recovery of usable invitation links and still-open candidate operations validate every original source ID against the current bank and governed visibility under exact-ID SHARE locks in numeric order. These later reads deliberately do not replace frozen content or keys after an editor correction. A hidden, missing or wrong-bank source blocks the whole form with the distinct PRECONDITION_FAILED code and manager-replacement-required guidance. It never resamples or changes saved answers or historical scored evidence. Terminal candidate receipts remain redacted. `state.ts` is a pure server-clock transition layer and allowlisted DTO projection. `store.ts` persists locked transitions.

The additive SQL is `drizzle/0087_recruitment_assessments.sql`: only `recruitment_assessments` and `recruitment_assignments`; UUID primary keys, original organization/member/email identity, JSON modules/questions/answers/score, integer millisecond BIGINT timestamps, consent/creator/revoker metadata, unique assessment/member invitation, org reporting and candidate indexes, and a short named assignment-to-definition FK. No existing table alteration. Registered in the forward manifest and applied once to the verified authoritative external database on November 27, 2026 after private full backup, fresh isolated restore and migration rehearsal. The ledger checksum and empty new tables were verified. Do not replay it or run a broad schema migration for this feature.

## Concurrency and lifecycle

All candidate operations, including lazy-finalizing reads, take organization SHARE then assignment UPDATE then exact seat and course subscription SHARE locks. Authorized already-elapsed attempts finalize and commit redacted receipts without source reads. Still-open forms then take sorted source-question SHARE locks, recheck exact access and term, and sample the clock again after those waits. A deadline crossed during either an approved or withdrawn-source lock wait finalizes durably before any source error is thrown. Annual mutations elsewhere lock the organization; that establishes a common ordering. Manager creation/invitation take organization UPDATE. List/results/revocation take organization SHARE, then delegated-manager membership SHARE where needed before any private definition/assignment lookup or not-found branch, then same-org assignment UPDATE locks in deterministic assignment-ID order. Candidate member SHARE locks are compatible with delegated-manager SHARE locks. Manager resolver preflight stays outside the transaction, with no global resolver while a pool connection is held. Transactions use READ COMMITTED. Only attempt state fields are mutable; invite identity, expiry and form content never reset.

Central entitlement preflight runs before acquiring a transaction connection to avoid starving the global database pool. Exact original-org access is then revalidated under transactional shared locks. Server time is captured after lock waits and access queries. Start preserves its original timer and consent, stale save revisions conflict, null clears an answer, and terminal states cannot restart. Submit requires a strict assignment ID plus expected revision; first active submission conflicts on a stale revision and scores only durable answers. Deadline finalization and terminal submit retries take precedence over revision checks. Timeout uses the deadline timestamp. Lazy finalization returns a terminal view and commits instead of throwing a rollback. Revoke retains existing completed score/answers/consent/timestamps. Repeated invites return the original assignment only while it is invited or active and its form, assignment expiry and timer remain usable; submitted, timed-out, expired or revoked duplicates return CONFLICT with a new-form-required message, never resetting or reinviting the old attempt.

Timed attempts automatically score durable choices when their deadline ends unless the assessment invitation was revoked before that deadline. Loss of seat/course access blocks further candidate operations but does not cancel the disclosed automatic scoring. Managers must revoke the assessment invitation before its deadline to stop that score. A timed-out score records saved choices, not proof of uninterrupted access, answering every question or practical competence. No historical access-loss reconstruction is attempted from current seat/course/subscription rows. Untimed attempts require manual submission before expiry; otherwise choices remain privately stored with no score, submitted timestamp or completion. Candidate countdowns are advisory only. Automatic blocking reconciliation is scheduled no earlier than the actual response receipt plus the remaining server-reported time, never from the conservative display or request-duration charge. Repeated cache merges cannot postpone that receipt anchor or reset bounded failed-read retries. This safe schedule may reconcile after the real deadline; every server action still enforces the actual deadline. Layout cleanup advances candidate scope epochs before unsent writes can dispatch, and cancels/removes only the exact assignment query so a remount cannot join an earlier session's read. Initial DTO admission requires an observed nonmanual fetch begun and completed in the current epoch. Known source withdrawal clears the candidate view, cache and confirmation immediately, distinctly from revision conflicts. Manager invitation-copy outcomes survive ordinary fresh reauthorization in an epoch-keyed parent, stay hidden during that read, and disappear on session reset, including when the clipboard is denied.

Before starting, candidate questions and answers are empty. Active questions use `candidateQuestions`; nonactive views hide prompts/options and return empty answers while durable evidence remains in the assignment row. Candidate DTOs never include answer keys, explanation, score, a database row or other candidates. Unscored manager results expose only metadata with empty questions and answers; scored results retain review and recompute scores from snapshot and durable answers based on the stored submitted timestamp, including completed attempts later revoked. List/results capture server time after all assignment and authorization lock waits, finalize overdue rows under lock, and persist only recruitment assignment transitions before the transaction commits and reporting returns. This prevents an accepted pre-deadline save that has not yet committed from being omitted by timeout scoring. Results, CSV and completion counts consume the committed finalization; summaries count stored submitted timestamps only. Repeated reports do not consume another revision or rewrite terminal rows. Completed rows never become expired.

Manager reporting is gated by fresh list/results authorization independently of the current-term catalog. An authorized historical report can retain CSV and revocation when catalog access is unavailable; creation and invitations still require a separate fresh current-term catalog gate. A catalog denial never establishes reporting authority. Every CSV click cancels a prior exact-scope results read and fetches fresh results with staleTime 0 and retry false. Download uses only that returned payload, with captured/live manager capability and assessment identity checks after both waits. A synchronous fence prevents duplicate exports. Remote authorization denial resets the private scope and evicts cached data; network failure, identity mismatch, session replacement or unmount never fall back to delivered props or trigger a late download. Existing CSV formula protection remains unchanged.

## Self-review and validation limits

The implementation was reviewed against the requested scope, exact shared DTOs, input validation, tenant scoping, identity priority, region and course sentinels, immutable snapshots, question leakage, status/revision/deadline boundaries, transaction lock order, pool starvation, audit persistence, and absence of entitlement/activity/billing/email writes. Catalog question pools and subscriptions are batched, not N+1 per candidate. Helpers accept typed database read boundaries and pure states for mocked testing. Service mocks verify reporting lock order, post-wait clock capture, historical authorization, persistence failure, idempotence and commit-before-return. The disposable MySQL regression holds an actual accepted save between UPDATE and COMMIT across a controlled server-clock deadline, confirms results/list stay pending, then verifies the winning answer and score are durable and repeat reports are idempotent; the hook delays only commit, not SQL execution or lock behavior.

Static compilation and safety-preloaded unit tests are local source checks only; exact results and source-review verdicts are reported in the dated Context Hub session. MySQL validation exports the current schema into a fresh disposable daemon inside an isolated network namespace. Actual desktop/mobile browser interactions use only intercepted synthetic APIs and are not proof of production identity, inbox/OTP delivery, refund propagation or cross-device customer persistence. No real candidate assignment, customer email, new seat, subscription, pricing, checkout, readiness, mock-exam or CEU writes were made. Source is saved for review, not published by this build task. V1 requires existing course-specific Annual sentinel rows; malformed or legacy differently-linked subscription data fails closed and is not repaired by this feature.
